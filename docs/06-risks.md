# 06 · 风险与开放问题

## 风险表

| # | 风险 | 可能性 | 影响 | 缓解 |
|---|---|---|---|---|
| R1 | 中文 TTS 音色不够自然 | 高 | 高 | 预留云 TTS 与 CosyVoice 接口；M1 就做 A/B |
| R3 | AEC 不佳导致自打断 | 中 | 高 | WebRTC APM；播放音量自适应；双阈值（能量 + 时长） |
| R4 | Rust 开发慢于预期 | 中 | 中 | 允许 TS/Electron spike；接口协议先冻结 |
| R5 | 模型许可不清 | 中 | 高（商用） | 建立 LICENSES 台账，商用前逐项确认 |
| R8 | 端到端延迟不达标 | 中 | 高 | 流水线重叠；首句短；就近节点 |
| R9 | 长时间对话内存增长 | 低 | 中 | 上下文裁剪；音频缓冲固定容量 |
| R10 | macOS 权限/签名问题 | 中 | 中 | 早期就做一次完整打包验证 |

## 风险详解

### R3 · 自打断
播放时麦克风必须开着才能打断，但扬声器的声音会被麦克风收进去。
两条防线：

1. **AEC 参考**：把正在播放的音频作为参考信号喂给 AEC，消掉自己的声音；
2. **判定门槛**：AEC 后的残余能量持续 > 200 ms 才算用户说话，单帧不触发。

兜底：外放音量过大时，自动降低播放音量或提示戴耳机。

### R5 · 许可
最容易在"能跑"之后被忽视。做法：

- 每个模型/音色记录：来源 URL、revision、哈希、许可、商用与否；
- 统一放 `assets/voices/LICENSES.md`；
- 任何"许可不明"的资产，默认**不用于商用版本**。

### R8 · 延迟
串行链路必然超 1.5 s。必须做的三处重叠：

1. ASR final 一到就发 LLM（不等整段稳定）；
2. LLM 第一句就发 TTS（不等全文）；
3. TTS 首包就开播（不等整段合成）。

## 开放问题

1. **语言范围**：只做中文，还是中英混说？
   会影响 ASR 与 TTS 的选型（SenseVoice 支持中英粤日韩）。
2. **自用还是商用**：决定许可策略、云服务选型、是否需要账号体系。
3. **要不要"记忆"**：长期人设与关系记忆，涉及存储、隐私与上下文管理。
4. **平台**：只做 macOS，还是 Windows 也要？
   Windows 的音频栈与打包会显著增加工作量。
5. **离线兜底**：断网时是"只显示文字"还是"切本地小模型"？

## 不做的事情（防止范围蔓延）

- 不做数字人、口型、照片级虚拟形象（2026-10-30 移出范围）
- 不做端到端语音模型（需要可检索文本与可替换的单点）
- 不做多人群聊、会议转录、翻译
- 不做移动端（M1 阶段）
- 不把 Python 变成必需依赖
