## M0.5 · 分项验证（当前）

**前一项不通过，不进入下一项。** 每一项都要留下可重跑的数字，而不是"感觉能用"。

| # | 分项 | 判据 | 状态 |
|---|---|---|---|
| 1 | 语音输入 + 实时字幕（中英） | 首字 ≤500 ms；更新 ≥3 次/秒；10 分钟不丢帧 | ✅ 首字 250–600 ms、约 3 次/秒；句末 SenseVoice 定稿（狸花猫/英文/标点均正确）；10 分钟长跑待做，[dev/01](dev/01-voice-input.md) |
| 2 | 中文 TTS（多音色） | 首句合成 ≤300 ms；盲听 ≥3.5/5；许可可商用 | 待做 |
| 3 | LLM 流式 | 首 token p50 ≤600 ms；断流可恢复 | 文字链路已通；真实 key 的 TTFT 待测，[dev/03](dev/03-llm.md) |
| 4 | 数字人渲染 | 720p 30 fps；口型偏差 ≤120 ms | 待做 |
| 5 | 全链路 + 3 个角色 | 首响 p50 ≤1.5 s；10 轮不崩 | 待做 |

为什么先做语音输入：它是唯一"做不好则整个产品不成立"的分项（延迟、丢帧、中文识别），
也是唯一能在没有 TTS / LLM 时单独量化的分项。

**退出条件**：五项都有实测数字与结论；M1 的技术路径（含 TTS 引擎与 3 个角色的音色）确定。

## M1 · 半双工语音闭环（2–3 周）

范围：按住说话 → ASR → LLM → TTS → 播放。**不做**数字人、不做打断。

- [x] cpal 采集（48 kHz 单声道；重采样交给 sherpa-onnx，暂不引 rubato）
- [x] 流式识别（sherpa-onnx streaming zipformer 中文；SenseVoice 保留为整段备选）
- [x] DeepSeek 流式调用（句末触发、可取消、上下文预算，见 [dev/03](dev/03-llm.md)）
- [ ] 回复的句子切分（TTS 前置）
- [x] 标点恢复（由 SenseVoice 定稿提供）
- [ ] TTS + 播放队列（引擎待 M0.5 第 2 项选型）
- [ ] 最小 UI：按住说话、字幕、状态指示（字幕与状态已有）
- [ ] 首启流程：API Key、模型下载、设备选择
- [ ] 录音落盘开关（调试用，默认关）

**验收**

| 项 | 标准 |
|---|---|
| 首响 | p50 ≤ 1.2 s、p90 ≤ 1.8 s（10 次） |
| 字错率 | ≤ 5%（50 句测试集） |
| 稳定性 | 连续 10 轮不崩 |
| 资源 | 空闲内存 < 1.5 GB |

## 排期原则

1. **先窄后宽**：M1 只支持中文、只支持一个音色、只支持一个 LLM。
2. **数字人最后接**：它不改变核心链路，晚接不亏。
3. **每周一个可演示的东西**：哪怕只是"说一句话，屏幕出现文字"。
4. **不并行开三条线**：同一时间只推进一个里程碑。
