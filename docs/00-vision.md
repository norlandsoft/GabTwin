# 00 · 愿景与范围

## 一句话

一个能与你实时闲聊的数字角色：有声音、有表情、有停顿，像一个在场的人，而不是一个聊天框。

## 为什么做

- 现有语音助手是"命令—响应"，不是闲聊；说完一句就冷场。
- 云端语音对话延迟高、隐私差，音频要离开本机。
- M1 Max 的算力已经够本地跑 ASR 和 TTS（实测见 [03](03-models.md)），LLM 走云即可。
- 市面上的数字人大多停在"播报视频"：文本先定、视频后生成，不能对话。

## 目标场景

1. **陪伴闲聊**：独处时有个能接话的对象，话题随意，不需要任务。
2. **口述**：说话即写作，转写结果可编辑（次要场景）。
3. **角色化互动**（本项目的核心形态）：从预设的 3 个角色里选一个，各有各的声音、性格与说话方式。
   不做用户本人的声音或形象克隆（见 [ADR-008](05-decisions.md)）。

## 非目标

明确不做，避免范围蔓延：

- 不做通用语音助手：不接智能家居、不做提醒、不抢系统助手的活。
- 不做会议转录、字幕、翻译工具。
- 不做照片级写实数字人：本机算力不足以实时逐帧生成（见 [06](06-risks.md)）。
- 不做用户本人的分身克隆：不做声纹克隆、不做人脸复刻（ADR-008）。
- 不做多人群聊、不做移动端（至少 M1 不做）。

## 成功标准

M1 结束时，以下四条全部满足才算通过：

| 指标 | 目标 | 测法 |
|---|---|---|
| 首响 | ≤ 1.5 s（中位数） | 按住说话到扬声器出声，10 次 |
| 转写准确率 | 字错率 ≤ 5% | 自建 50 句中文测试集，安静环境 |
| 稳定性 | 连续 10 轮不崩 | 脚本连续对话，含打断与空输入 |
| 离线可用 | 除 LLM 外全本地 | 断网后仍能完成识别与合成 |

## 体验目标（非量化）

- 它应该在你说完之后**马上**接话，而不是等一个"正在思考"的转圈。
- 它被打断时应该**立刻闭嘴**，而不是把缓冲里的话播完。
- 它不说话的时候也应该**活着**：眨眼、呼吸、轻微点头。

## 名字

GabTwin = gab（闲聊）+ twin（成对的人）。"twin"指与你对话的那个角色，
不是你的复制品。名字暂保留，含义已按 ADR-008 收窄。
